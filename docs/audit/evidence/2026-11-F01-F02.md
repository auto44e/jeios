## F01 — mutation runner must not manufacture green evidence — status: ADDRESSED

Files: `tools/mutants.py` (rewritten), `tools/mutants.json` (manifest comment +
corrected ARM entry), `.github/workflows/ci.yml`, `Makefile` (`mutants` target
unchanged).

Reproduced defect (baseline, pre-fix), from the gate's evidence appendix: a
killer that exits 1 before any mutation was classified `KILLED`. Verified against
the pre-fix runner in this environment: `('KILLED', '')` with the source
unchanged — a false green.

Repairs:
- **Baseline preflight.** `apply_one` now builds+runs the killer on pristine
  snapshot source in the mutant's own configuration FIRST and requires exit 0; a
  red/crashed/timed-out/unbuildable baseline is `BLOCKED`, never `KILLED`.
- **Isolation.** Every build/run happens in a private `tempfile.mkdtemp`
  snapshot of the tracked working tree, produced via a transient git index
  (`GIT_INDEX_FILE` + `read-tree HEAD` + `add -u` + `write-tree` + `archive`) so
  uncommitted tracked edits are captured WITHOUT touching the caller's real index,
  HEAD, or worktree. The snapshot is `rmtree`d in `finally`. The caller's
  worktree is never written.
- **Process-group timeout.** Children run with `start_new_session=True`; a
  timeout `killpg`s the whole group. A timeout is `BLOCKED` unless the mutant is
  declared `liveness: true` (then a non-terminating mutated run is the kill), and
  a liveness mutant still requires a passing bounded baseline.
- **Compile failure is BLOCKED, never a kill.** The `build_fail_is_kill` escape
  hatch is removed.
- **Manifest schema validation.** Non-empty unique ids; required string fields;
  path containment (reject absolute or `..` in `file`/`build`/`run`);
  `equivalent: true` requires a non-empty rationale; non-empty mutant list.
- **Distinct outcomes + machine-readable output.** KILLED / SURVIVED / BLOCKED /
  EQUIVALENT / SKIPPED; `--json` writes results; exit 0 iff every enabled mutant
  is KILLED or justified EQUIVALENT (SURVIVED and BLOCKED both fail).
- **Corrected manifest.** The misleading `GAP-ARM-AUDIT-CYCLE` (infinite
  recursion) entry is replaced by `GAP-ARM-AUDIT-FOREIGN-SIBLING`, matching the
  gate's confirmed defect (unvalidated sibling dereference in
  `audit_alias_scan`), still disabled pending its killer test (F04).

Acceptance evidence:
- `python3 tools/mutants.py --selftest` → `SELFTEST OK` (10 cases): real kill,
  red-baseline→BLOCKED, survivor, compile-failure→BLOCKED, source-drift→BLOCKED,
  empty/duplicate-id/unjustified-equivalent/abs-path manifest rejection,
  worktree-untouched.
- Post-fix false-kill reproduction now returns
  `BLOCKED — baseline killer FAILED on pristine source (exit 1)`; worktree
  source unchanged.
- `make mutants` → `6 killed, 0 equivalent, 0 SURVIVED, 0 BLOCKED, 4 skipped`,
  exit 0. All six existing anchors still produce genuine kills through the new
  preflight+isolation path.

Residual / not done here: per-mutant parallelism beyond `make -j` inside a
snapshot; a declared-liveness example mutant (none needed yet); enabling the four
gap mutants (each waits on its killer test under F04/F08/F09).

### F01 adversarial review (Codex, xhigh) — findings and dispositions

An adversarial peer review of the rewritten runner was run; its load-bearing
findings were fixed and are covered by self-tests:
- Non-boolean `liveness`/`equivalent`/`enabled` (e.g. `"false"`, which is truthy)
  could force a false KILLED — now rejected by schema validation (must be a JSON
  boolean); a build-phase timeout is never a kill. *(self-test: non-boolean
  liveness rejected.)*
- An all-disabled manifest, or `--id` selecting only a disabled mutant, printed
  OK — now FAILS (exit 1); an empty assurance run is not a pass. *(self-tests:
  all-skipped FAILS, selecting-only-disabled FAILS.)*
- Missing `run`, a non-string `equivalent_reason`, or non-string `env`
  values crashed with KeyError/AttributeError/TypeError — now clean validation
  errors (exit 2). *(self-tests: missing run / non-string env rejected.)*
- A tracked SYMLINK could redirect the mutation write outside the snapshot to the
  caller's real file — now refused (symlink and out-of-snapshot realpath both
  BLOCKED).
- A `build`/`run` value that is a command-line option (e.g. `-C/etc`) could inject
  Make behavior — now rejected (no leading `-`). *(self-test: build-as-option
  rejected.)*
- Text-mode read/write normalized CRLF across the whole file (a local mutation
  could change unrelated bytes → false KILL) — now byte-exact binary read/write.
- Snapshot subprocesses (`git`/`tar`) had no timeout/error conversion — now
  bounded and converted to BLOCKED.

Accepted residual limitations (documented, not silently ignored):
- A killer that depends on mutable EXTERNAL state (e.g. a `/tmp` marker) could in
  principle be flaky across the baseline/mutated runs; the project's killers are
  deterministic hosted unit tests, and this is noted as a manifest-authoring
  constraint rather than a runner guarantee.
- A mutated child that double-forks + `setsid` can escape `killpg`, and a
  `kill -9` of the runner itself leaves a `/tmp/jeios-mut.*` dir; these are
  inherent to a subprocess wrapper and are not claimed to be fully solved.
- `git archive` emits canonical content, so a repo using clean filters / LFS /
  CRLF attributes would snapshot canonical rather than exact working-tree bytes;
  JeiOS uses none of these.


## F02 — ordinary builds and container execution must be trustworthy — status: ADDRESSED

Files: `Makefile`, `tests/test_*.c` (NDEBUG guard), `.docker/Dockerfile`,
`.docker/ci-run.sh`, `.docker/README.md`, `.github/workflows/ci.yml`.

Repairs:
- **`test_sched_killall` prerequisite.** The rule listed `kernel/core/device.c`
  (neither compiled nor `#include`d) but not `kernel/core/sched.c` (the
  `#include`d TU), so editing `sched.c` did not rebuild the test in an ordinary
  `make`. Prerequisite corrected to `… sched.c proc.c …`. Verified: `touch
  kernel/core/sched.c` now triggers a rebuild of `build/0/test_sched_killall`.
- **NDEBUG vacuity.** 10 assert-based tests lacked a guard (4 already had one);
  added `#undef NDEBUG` before `#include <assert.h>` in all 10, so a `-DNDEBUG`
  build cannot silently make their asserts vacuous. All 14 assert-using tests now
  guarded.
- **Container build isolation.** `ci-run.sh` default mode now clones the tracked
  tree into a container-private dir and builds there, so a poisoned/stale host
  `build/` is not visible and the result is a clean rebuild (verified: the host
  `build/` directory is absent in the clone). `--in-tree` is an explicit opt-in
  for fast local iteration via a RW bind mount.
- **Soak-count validation.** A non-integer, zero, or out-of-range iteration count
  is rejected (exit 2); zero no longer "succeeds".
- **Signal handling.** SIGINT/SIGTERM clean up the container and exit 130 rather
  than falling through into the next soak iteration.
- **Reproducibility claim corrected.** The Dockerfile and README now state that
  the base is digest-pinned but the apt packages are NOT version-pinned and the
  QEMU check constrains only major.minor; `/etc/jeios-toolchain` records the exact
  dpkg versions + image id as the cited evidence. "Pinned base + recorded
  versions", not a bit-for-bit clean-build guarantee.
- **Honest teardown.** README states a `kill -9`/host crash cannot run the trap;
  unconditional cleanup after an uncatchable kill is not claimed.
- **CI.** `container-parity` records image id + toolchain and runs the ISOLATED
  `ci-run.sh check`/`mutants` (not a shared RW bind mount).

Acceptance evidence:
- `touch kernel/core/sched.c` → `make -n build/0/test_sched_killall` shows a
  recompile.
- All 14 assert tests contain `#undef NDEBUG`.
- `ci-run.sh soak {0,-1,abc,1.5}` → exit 2 "must be an integer"; empty → 20; 3 → 3.
- Isolated `ci-run.sh check` and `ci-run.sh mutants` pass under Docker 29.1.3;
  the host `build/` is not present in the container's clone.
- `ASAN_OPTIONS=detect_leaks=0 make check` → exit 0 (ASan/UBSan retained; leak
  detection remains an explicit environment-limited exception, not claimed
  coverage).

Residual / not done here: a supported leak-enabled CI lane (LeakSanitizer is
blocked in this sandbox); `-i/-t` are used only for the documented interactive
`shell` task, not for non-interactive CI.
