## F07 — endpoint corruption must not become an ordinary unsupported status
*(owner-approved contract change)*

Added `JE_EP_UNWIRED` to the `je_ep_status` enum (`include/jeios/endpoint.h`) for
the EXPECTED "vm not wired" condition, distinct from `JE_EP_CORRUPT`, which is now
an INTERNAL invariant break only. The three unwired sites
(`endpoint_kern.c` create/dup/seed, gated by `!je_endpoint_kern_is_wired`) return
`JE_EP_UNWIRED`. `ep_status_to_abi` (`syscall.c`) maps `JE_EP_UNWIRED` →
`JE_ABI_UNSUPPORTED` (unchanged user-visible behavior for that case) and routes
`JE_EP_CORRUPT` to `syscall_invariant` (`_Noreturn` fail-stop) — a dangling/stale
record or lease/enum mismatch now halts the kernel instead of being handed back to
ring 3 as `JE_ABI_UNSUPPORTED`.

Safety: no well-formed user handle can reach the internal `JE_EP_CORRUPT` —
`object_to_end` runs only after the handle table confirms a LIVE, gen-matching
ENDPOINT slot, so a malformed/stale/wrong-type handle still gets
BADINDEX/STALE/WRONGTYPE before corruption can be observed. The pure-layer
resolve precedence is the host-tested proof of this (`EP-RESOLVE-PRECEDENCE`
mutant). The UNWIRED→UNSUPPORTED and CORRUPT→fail-stop ROUTING lives in
`endpoint_kern.c`/`syscall.c`, neither linked into a hosted test, so it is
QEMU-integration + code-review covered (stated honestly in the test comments).

**Cross-review catch (important):** the adversarial review found that the
caller-identity check at `endpoint_kern.c` (`creator.gen == 0u`, etc.) returned
`JE_EP_CORRUPT` and WAS user-reachable — an unregistered user thread
(`proc_id == NONE`, which `je_thread_create_user_start` permits) invoking
`ENDPOINT_CREATE` would have hit the new fail-stop, a user-triggerable panic / DoS
— exactly the failure mode the gate warns against. Fixed: that caller-identity
mismatch now returns `JE_EP_DENIED` (a returnable authority rejection), not
`JE_EP_CORRUPT`. Only genuinely impossible internal states keep CORRUPT. Stale
`JE_EP_CORRUPT` references in `endpoint_kern.h` were corrected to `JE_EP_UNWIRED`.

## F08 — explicit one-thread-per-process *(owner-approved contract change)*

`je_thread_create_user_start` (`sched.c`) now scans for an existing `THREAD_USER`
with the same `(vm, index)` and returns `JE_ERR_INVALID` before allocating a slot,
instead of relying on the incidental `je_arch_page_guard` / `je_proc_link`
failure. Hosted-tested in `test_sched_killall` (duplicate create rejected, a
distinct `(vm,index)` still succeeds, first thread untouched). Mutant
`F08-ONE-THREAD`.

## F09 — VM audit and device authority negative coverage *(test-only)*

Added `vm_fake` test-support hooks (`poke_alias`, `poke_extent_phys`) and a
negative test for each `je_vm_audit` rejection class — alias, one-to-one, guard,
completeness, cross-process sharing, upper-flags, kind/perm, ownership, distinct
roots — each poking exactly one invariant, asserting INVALID, restoring, asserting
OK. (The raw illegal-perm class is fake-unreachable and documented as covered by

REPLACES a leaf's phys so completeness doesn't mask it). Device: full
`je_device_apply_dispatch` authority coverage (owner / non-owner / revoked /
inactive / gen-0 / kernel-dispatch), `on_process_dying` revocation, non-owner ack,
quota/no-slots preflight, invalid caller — `test_device` now 171 checks. Enabled
`GAP-DEV-DISPATCH-OWNER`. No kernel change. x86 trap-routing coverage is flagged
as a follow-up (needs an owner-gated `JE_X86_TRAP_HOSTED_TEST` seam; the ARM GIC
fake does not substitute).

## F10 — syscall glue, receive staging, image registry

- **Recv staging clamp** (`syscall.c`, defensive): both recv paths now pass
  `je_syscall_recv_staging_cap(cap, sizeof staging)` = min(user cap, buffer size)
  to the peek, removing the dependency on the `mlen ≤ JE_EP_MSG_MAX` enqueue
  invariant. User-visible SHORT_BUFFER/length semantics unchanged (verified). The
  helper is externally linkable so `test_syscall` checks it. Mutant
  `RECV-STAGING-CLAMP`.
- **Image span arithmetic** (`image.c`, defensive): `je_builtin_images_init`
  computes the spawn-child linker span on `uintptr_t` instead of pointer
  relational/subtraction across distinct objects (C11 UB), with a `_Static_assert`
  that the span fits `size_t`. Same reject condition and length.
- **New hosted `test_image_registry`** links `image.c` with fake linker symbols
  (one link per case via `-DJE_REG_CASE_*`): a well-formed registry inits;
  length-mismatch and missing-supervisor-report roll back. Mutants
  `IMAGE-REGISTRY-PUBLISH-GATE` and `IMAGE-SUPERVISOR-REPORT` (KILLED).
  `IMAGE-SPAN-GUARD` is registered **EQUIVALENT** with a tripwire rationale: the
  validator already rejects both degenerate spans (`e==s` → entry offset 0 in no
  RX byte; `e<s` → length wraps past memory_size), so the guard is defense in
  depth today; if the validator changes so the guard becomes load-bearing, the
  equivalent declaration flips to a visible SURVIVED.
- **Deferred/flagged:** the recv mint/copy/rollback/commit shared-helper refactor
  stays owner-gated (characterize in tests first). A separate out-of-scope
  observation surfaced: both recv paths cast `(uint8_t)hcap`, truncating a
  user cap count of 256 to 0 — believed to cause only a false SHORT_BUFFER (never
  a larger kernel bound); flagged for a follow-up fix-gate item, not changed here.

## F11 — ARM native proof gaps

`vectors.S` + `main.c`: the returning-IRQ canary now catches register corruption
LATE in the interval (a full-register re-check across the whole test window, not
just the primary x0–x28 phase), setting the offending register in the fail
observable; and a stalled timer is now bounded internally with an explicit
`FATAL timer stalled` serial marker + halt, rather than relying only on the
external smoke `--timeout`. The smoke oracle (`tools/smoke_arm.py`) gained a
negative-image generator that patches a canary-check site (or the timer path) to
PROVE the proof fails when it should, plus recognition of the new FATAL markers;
`tools/test_smoke_arm_timer.py` self-tests the oracle. No injection code ships in
the kernel — the oracle mutates the built image. New profiles
(`--late-corruption low|high`, `--stalled-timer`) FAIL as required:
`FATAL irq canary-hi mismatch reg=0`, `reg=29`, `FATAL timer stalled`.
