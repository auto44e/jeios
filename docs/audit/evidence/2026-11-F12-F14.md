`kernel/core` from **49 → 0** by moving cross-TU `extern`s to owned headers,
adding missing prototypes (or marking file-local functions `static`), and
removing redundant redeclarations (incl. a new `include/jeios/memory.h` owning
the memory-subsystem prototypes). Also: SPDX headers added to original files that
lacked them; stale endpoint/scheduler comments corrected; the redundant second

change. Deferred (would touch tested layout): the device test-observation-state
split, and any dead-parameter removal (the `release_table_owned` `owner` param is
owner-gated and untouched). The 3 flags were NOT added to the Makefile `WARN`

standing gate remains `-Wall -Wextra -Werror -Wconversion -Wshadow`.

Verified: `make check`, `make aarch64`, `make smoke` pass; core warning count 0.

## F13 — core/test seams and the pre-MP3 lifecycle decision

**Spawn observer decoupling (safe mechanical change):** `je_proc_spawn` no longer
calls a harness-only symbol that can `fail()`/halt after commit. `spawn.c` now
has a registered `spawn_commit_observer` (default NULL = core no-op) and a
set-once `je_spawn_set_commit_observer` (declared in `spawn.h`); the post-commit
call is `if (spawn_commit_observer) spawn_commit_observer(id, image_id)`. The
harness (`main.c`) provides the observer as `m4f_record_image`, registered in
`m4f_seed_supervisor` after the empty-baseline check (no spawn can race it). Per
the new observer contract (infallible-to-core), an identity violation no longer
halts inside the spawn syscall — it latches `m4f_ledger_identity_bad` and the
harness fail-stops from its own context (`m4f_assert_ledger_identity`, same
message, run with interrupts off so nothing commits between check and
corroboration). A `make check` seam assertion was added: no symbol in `spawn.o`
may be an undefined global defined by `main.o`.

Behavior-preserving proof: smoke (modes 1–15) and integration ledger markers are
byte-identical to the pre-change baseline except for value-only fields unrelated
to spawn (a TSC `spawn cycles=` timing that varies between baseline runs too,
PANIC `rip=` code addresses, QEMU pids, and the layout-dependent M2 `free pages=`
printed before any spawn/scheduler code).

**main.c physical fixture split — DEFERRED** (owner-gated): 3874 lines / 44
`JE_TEST_MODE` blocks; the gate defers the mechanical move until after the defect
fixes. Recorded as a follow-up, not done this batch.

**Pre-MP3 lifecycle ownership — DECISION RECORD** (`docs/adr/0014-...`): a bounded
lifecycle-only extraction (process registration, link, dying/reaping, VM+kstack
lifetime, arch ops behind seams) with a single ownership boundary and named
no-regression gates, plus an **explicit migration trigger** for the eventual
`sched.c` → `sched_rr.c` move (next scheduler feature, or a cross-arch parity
claim). Recorded as proposed/owner-gated; implementation deferred and kept as a
**pre-MP3 blocker**. ADR 0013's trigger-less "migrate later" flex is amended to
point at this trigger. `sched.c`/`sched_rr.c` untouched.

## F06 owner dispositions (owner-approved 2026-11-06, flex to revisit)

1. **vb_flush → keep the no-op, assert the precondition.** `je_arch_cpu_policy_init`
   (`trap.c`) now explicitly clears CR4.PGE and CR4.PCIDE, tying the no-op's
   correctness (single-BSP, CR3-reload-flushes, no global pages, no PCID) to an
   enforced invariant. If PCID/global pages are ever introduced these clears make
   the omission fail fast. `je_arch_cpu_policy_cr4()` reads it back. No scoped
   invalidation, no PCID/SMP work. Smoke confirms boot unaffected.
2. **Zeroization → keep the distributed policy (no-change, documented).** Every
   user/page-table exposure zeroes on build (`vm.c build_page`) / link (table
   clear) and VM frees scrub; no demonstrated leak. Not collapsed to one point.
3. **Boot-block RAM profile → do not tighten (no-change, documented).**
   Loader-owned reserved (non-type-1) RAM is permitted for the boot block; the
   contract is "accessible via the bootstrap identity map, not necessarily a
   type-1 entry." The existing image-in-RAM check stays.
4. **No-NX console line → reworded (small change applied).** `main.c` now prints
   "(W^X enforced)" with NX and "(DEGRADED: NX absent, kernel data/heap/stack
   executable, user VM refused)" without, retaining the `M1: protected mappings`
   prefix the smoke/integration oracles match. Verified: NX-present and no-NX
   smoke both pass.
