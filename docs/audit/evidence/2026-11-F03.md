# Fix-gate closure evidence — F03 (reaper sign + scheduler failure/lifetime tests)

Observed 2026-11-06. Branch `fix/gate-f03-reaper-sign` off core `main`
`a7b4d4c`. F03 is a confirmed owner-gated defect in tested M3a scheduler code.
AI-assisted multi-agent work (Codex implementor, Claude test author, Codex
adversarial cross-review, lead orchestration + verification); **not** independent
human qualification. Local hosted + container evidence; the AMD64 QEMU
integration proofs remain the CI `bootstrap` job's responsibility.

## Defect

`int je_sched_reap_dead(void)` (`kernel/core/sched.c`) is documented
(`include/jeios/sched.h`) as "Returns count reaped, or a NEGATIVE je_status on
violation," and every caller checks `< 0` (11 sites in `kernel/core/main.c` +
`je_kernel_idle_step`). But the error returns were POSITIVE — `(int)JE_ERR_BUSY`
(==5) and `(int)s` (je_status 1..7). So the `< 0` guard was DEAD: a
`je_sched_drop_user` failure or a liveness-guard violation was miscounted as "N
reaped" and the idle loop would retry forever instead of halting. A real false
pass also existed at `main.c` (the `!= 1` endpoint-reap check): a `drop_user`
`JE_ERR_INVALID` returned `+1`, which equalled the expected count and passed.

## Fix (narrow, per the gate)

- Negated all five error returns (`-(int)JE_ERR_BUSY` at the 4 liveness/context
  guards, `-(int)s` at the `drop_user` failure); counts (0..`JE_THREAD_MAX`-1)
  and negated errors (-1..-7) cannot collide. The `abort_scheduler()` sites for
  `je_vm_destroy_owned` / `je_proc_on_reaped` failures (unrecoverable
  mid-teardown) are unchanged.
- Replaced the inline `pushfq`/IF-check with a new arch seam
  `bool je_arch_irqs_enabled(void)` (`include/jeios/arch.h` + x86
  `kernel/arch/x86_64/platform.c`, `"memory"` clobber), so the interrupts-off
  precondition is enforced via a function a hosted test can override — the raw
  `pushfq` previously made the reaper abort unconditionally in a hosted process,
  leaving its error paths untestable. Contract text in `arch.h` forbids a
  weak/hardcoded-false stub (every port must report real IF state); the hosted
  override defaults to interrupts-off and only the IF-precondition test enables.
- Documented the PARTIAL-PROGRESS contract in the reaper's comment: a negative
  result leaves the FAILING slot untouched, but earlier DYING slots may already
  be reaped in the same call; the error is FATAL and must not be retried. A
  validate-then-mutate preflight (which would make "negative => nothing mutated")
  was deliberately NOT adopted — that is a behavior change reserved for the
  owner; this PR is the narrow sign fix.

## Tests (`tests/test_sched_killall.c`)

Replaced the `je_arch_halt` infinite-loop stub with a `setjmp`/`longjmp` catch
(counts aborts; an unarmed abort exits non-zero rather than hanging), and added
test-controlled fakes for `je_arch_irqs_enabled` (defaults off),
`je_arch_cr3_read`, `je_arch_tss_get_rsp0`, `je_arch_page_restore` (injectable
failure + records addresses), and `je_vm_destroy_owned` (records `(vm,index,
proc_id)`, scheduler-removal-before-destroy, and record state at the call). New
cases (each asserts STATE, not just the return):
1. not-ready / wrong-context → exactly `-5`, no arch/VM state touched.
2. IF enabled → `abort_scheduler` fired (caught, no hang), no destroy, slot still
   DYING.
3. active CR3 → `-5`, no restore/destroy; plus a non-matching-CR3 slot that DOES
   reap.
4. active RSP0 → `-5`, same no-side-effect assertions.
5. `drop_user` failure (injected `page_restore` → `JE_ERR_IO`) → exactly `-6`, no
   destroy, no `on_reaped`, slot/record still DYING, no abort.
6. two DYING slots, slot 2 hits a guard → slot 1 reaped once with exact args,
   slot 2 untouched, `-5` (partial progress).
7. 0-reap → 0; N-reap → N with exact per-slot destroy/restore args, a READY peer
   untouched, a second call returns 0.
   Plus a post-drop fail-stop case (destroy / `on_reaped` failure aborts).
Success/partial fixtures use a vm_index DISTINCT from the slot number so a
`idx=i` regression is caught. The original kill-all cases are retained.
Result: `test_sched_killall` PASS, 226 checks (was 66).

## Cross-review and residual gaps

A Codex adversarial cross-review (different lineage from the Claude test author)
confirmed the five registered mutants are genuinely killed (no false pass) and
identified coverage gaps; the two highest-value (`idx=i` via slot≠vm_index, and
the RSP0 guard mutant) were closed in a second worker pass. Documented residual
gaps, deferred as not part of this narrow fix:
- a `proc_id.gen == 0` legacy-slot fixture + a `REAPER-GEN0-GUARD` mutant (needs
  a new identity shape);
- a high-slot (slot 15) fixture + a loop-bound mutant;
- the `i == current` guard is unreachable after the earlier `current != 0` check,
  so it is not independently tested;
- the hosted `je_vm_destroy_owned` is a recorder, so real VM frame/stack freeing
  is proven by QEMU smoke, not this hosted test.
