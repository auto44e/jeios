## F04 — ARM audit: validate every table address before dereference

**Defect (confirmed, ASan SEGV).** `je_arm_mmu_audit` proved a freshly-built,
not-yet-enabled ARM table safe before `je_arm_mmu_enable`, but its leaf-triggered
`audit_alias_scan` re-walked from the root and dereferenced child-table pointers
that `audit_table` had not yet validated (off-path siblings). A tampered
`root[511] = 0x30000000|3` made the alias scan dereference `0x30000000`.

**Fix — two-pass restructure** (`kernel/arch/aarch64/paging.c`, `paging.h`):
- **Phase 0 preflight:** clear `je_arm_last_audited` UNCONDITIONALLY on entry (so
  any audit call — a failed re-audit, or `audit(NULL)` — revokes a prior pass);
  validate `1 <= table_count <= JE_ARM_MAX_TABLES`; validate the table region
  bounds; validate every ledger `table_pa[i]` is page-aligned, unique, AND within
  `[table_start, table_end)` BEFORE any dereference; root must be a ledger member.
- **Phase 1 structural walk:** a work-list + a visited bitmap over ledger ordinals
  (depth <= 4); reject a child that is not a ledger member (FOREIGN), misaligned,
  or already visited (REVISIT: self-cycle / ancestor-cycle / shared/repeated);
  require `visited_count == table_count` (UNREACHED otherwise).
- **Phase 2 leaf checks** over the recorded L3 tables only — never follows a raw
  descriptor pointer. Independent descriptor literals / identity (VA==PA) / class
  / AF/AP / W^X and the alias scan are preserved; the alias scan now traverses
  only Phase-1-validated tables.
- New hosted observability in `paging.h`: `je_arm_mmu_last_audit_reject` (enum:
  NONE/LEDGER/COUNT/ROOT/MALFORMED/FOREIGN/REVISIT/UNREACHED/LEAF/ALIAS/
  PRECONDITION) + `je_arm_mmu_last_audit_reads`, so tests assert the exact reason.

**Tests** (`tests/test_paging_bits.c`): 33 new structural tamper cases, each
asserting INVALID + the exact reject reason + enable-refused, with foreign targets
as `mmap(PROT_NONE)` pages (deterministic fault). The pre-existing 23 leaf tampers
still pass. A `check_mirror()` guard pins the test's private-struct mirror against
layout drift.

**Mutants** (all enabled, all KILLED): ARM-AUDIT-FOREIGN-SIBLING,
ARM-AUDIT-REVISIT, ARM-AUDIT-COUNT, ARM-AUDIT-STAMP-CLEAR,
ARM-AUDIT-LEDGER-WINDOW, ARM-AUDIT-ALIAS. (The disabled
`GAP-ARM-AUDIT-FOREIGN-SIBLING` marker — which had corrected the earlier, WRONG
"infinite recursion" claim — is now replaced by the enabled FOREIGN-SIBLING
mutant.) Honest note on ARM-AUDIT-ALIAS: under the identity (VA==PA) contract a
cross-leaf alias also implies a non-identity leaf, so removing the scan still
yields INVALID (reason LEAF) at the second leaf; the mutant is killed by the
exact-reason assertion, proving the scan is reachable and classifies correctly,
not that it is the sole barrier (matches the design review's "redundant under
identity" finding).

**Cross-review (Codex, impl lineage reviewing Claude's tests) found two blockers,
both fixed:** C4 (NULL-audit left eligibility — fixed by the unconditional stamp
clear) and C2 (a well-formed-but-foreign ledger entry was dereferenced — fixed by
the `[table_start, table_end)` membership check). Three suspected C7 off-by-ones
were audited and found already correct (`table_ordinal` bound, bitmap `/64 %64`,
work-list admits 128).

## F05 — usercopy defensive contract + direct tests

**Fix** (`kernel/core/usercopy.c`, `include/jeios/usercopy.h`):
- Reject a NULL kernel buffer for nonzero length BEFORE the scheduler/scope (after
  the zero-length early return, which still succeeds touching nothing) — internal
  misuse, not a ring-3 exploit.
- Reject a nested copy while a scope is active, WITHOUT clearing the outer scope.
- Corrected the inaccurate scope comment; documented the NULL, nonnesting and
  interrupts-off/single-CPU preconditions in the header (no SMP/per-CPU promise).
- The fixup predicate and span validators are untouched.

**Tests** — a NEW `tests/test_usercopy.c` (links `usercopy.c` with a `je_vm_ops`
fake + scheduler stub + crafted-frame fixup hook): zero-length (incl. NULL),
NULL-kptr both directions, no-current-user, span structure (below/past arena,
wrap, non-canonical), span pages (absent, write-to-non-RW, read), page crossing,
happy-path FROM/TO with scope cleared, the fixup matrix (exact/nearby RIP, CR2
endpoints, PFEC, wrong owner), and nesting. The nesting case probes at
`outer+7` — inside the outer 8-byte span but outside a clobbered 1-byte nested
span — so it kills a "clobber-without-clear" mutant (verified by hand).

**Mutants** (enabled, KILLED): UCOPY-NULL-KPTR, UCOPY-NONNEST, UCOPY-WRITE-PERM.

**Cross-review (Claude)** confirmed F05-1/2/3 correct and found the original
nesting test too weak (same-span probe); strengthened as above.

## F06 — defensive validation subset (owner-gated contract items deferred)

Six pure-defensive items — each verified NOT to change behavior for any valid
caller (the cross-review confirmed every change is unreachable on a valid path or
only stricter on paths that already panicked):
1. `boot.c`: propagate the three initial `reserve()` statuses (unfailable today;
   future-proofs a capacity/policy change). Tests added.
2. x86 `paging.c` `je_arch_paging_init`: bound `ctx->map_count` and check
   `base+length` overflow before indexing `map[]` (valid contexts unaffected —
   `je_boot_parse` already enforces both).
3. ARM `physmem.c`: shared overflow-safe range/page-end helpers; `range_contains_
   page` and `range_intersects_page` now have parity and BOTH fail SAFE on
   overflow (a cross-review fix: intersects now returns `true`, not `false`, on a
   page-end wrap). Wrapping-range tests added.
4. x86 `vm_backend.c`: backend-local refusal to install a W&&X user leaf when NX
   is absent (defense-in-depth behind the existing `je_vm_build_quota` gate; uses
   the existing `JE_ERR_UNSUPPORTED`; never fires on an NX-present build).
5. x86 `vm_backend.c`: assert the inactive-root invariant BEFORE the first free in
   teardown (moves an already-fatal panic earlier; valid teardowns check the root
   first, so unaffected).
6. x86 `paging.c` `je_arch_page_restore`: a guarded-page bitmap so restore only
   un-guards a page that was actually guarded (rejects restoring a never-mapped
   hole). Symmetric with the existing guard CAS; the real scheduler guard/restore
   pairs still work.

## Owner decisions deferred (NOT taken — require owner disposition)

Per the gate, these F06 items are contract changes, not defensive hardening, and
are surfaced for the owner rather than decided by an agent:
1. **`vb_flush` invalidation semantics.** Today it is a no-op that is correct only
   under the documented single-CPU/no-PCID/inactive-root preconditions (now
   asserted earlier by item 5). Choice: (a) formally assert the PCID/PGE-off +
   single-CPU preconditions at boot, keeping the no-op; or (b) implement a scoped
   invalidation. This PR did neither (no PCID/SMP work, per the gate) beyond the
   earlier inactive-root assert.
2. **Single zeroization enforcement point.** No demonstrated leak exists (every
   user/page-table exposure zeroes on build/link; VM frees scrub). Whether to
   collapse the distributed policy into one enforced "zero-before-expose" point is
   an ownership-policy decision.
3. **Boot-block-in-RAM requirement + module eligibility profile.** The loader
   profile does not define whether the multiboot block may sit in loader-owned
   reserved (non-type-1) RAM. Tightening the parser could reject boots accepted
   today; needs the contract settled first.
4. **Rewording the no-NX "protected mappings … ready" console line.** It is
   printed unconditionally even in the degraded profile; rewording changes
   observable console output that smoke oracles may match on.
