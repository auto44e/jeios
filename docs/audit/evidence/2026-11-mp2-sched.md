## Proof: ≥2 threads, mapped+guarded stacks, per-slot counter table

Four kernel threads were created (slots 1–4): two proof workers (1,2) running the
register/NZCV canary, plus proof-only sentinel (3) and monitor (4) slots. Each

`dispatched = 24 = preemptions 8 + nonpreempt_switch_ins 16`, every worker meets

`dispatches_after_exit==0`. The READY bounded-wait invariant held.

## Proof: distinct GPR + NZCV survive every resume

The worker canary (`sched_arm.c`, `je_arm_worker_canary`) keeps x0..x30 live across
preemption, seeded per-slot from `je_arm_sched_rodata_patterns`, and writes a
per-slot NZCV pattern (`je_arm_nzcv_patterns`) via `msr nzcv`, then after the
returning IRQ re-reads NZCV (`mrs`) and every GPR and compares against the expected
per-slot values. A mismatch calls `je_arm_sched_canary_failure`. Save-side NZCV is
proven from `tf->spsr` in the handler; restore-side from the post-ERET `mrs`.
`verified_resumes>=1` and `nzcv_window_preempts>=1` per worker confirm a preemption
landed inside the register-live and NZCV-live windows and the state survived.

## Proof: guard-page fault

```text
sched guard target=0x40007000
EXCEPTION vector=0x4 ec=0x25 il=0x1 iss=0x47
  esr=0x96000047 elr=0x40088a04 spsr=0x200003c5
  far=0x40007000 vbar=0x40080800
sched guard PASS (thread guard translation fault; FAR==guard; ELR==store site)
```

The guard target `0x40007000` is a page in the allocator window (checked by the
oracle against the ELF, and asserted not to be the boot `__stack_guard`). The
syndrome is a current-EL data abort (EC 0x25), translation fault at level 3
(FSC 0x07), write (WnR=1); `FAR==guard`; `ELR==je_arm_sched_guard_store_site`. The
synchronous-exception SPSR preserves the monitor-masked I bit (the one expected
difference from a returning scheduler frame, whose validator requires I clear).

## DDI0487 citations confirmed in-code

- **WFI waking on a PSTATE.I-masked IRQ.** `sched_arm.c` `arm_wfi()` documents, and
  the proof relies on, DDI0487: `WFI` may wake for a pending interrupt while
  `PSTATE.I` is masked; the IRQ is not *taken* until I is cleared. The idle/sleep
  loops therefore `wfi` with I masked and only then `daifclr` to take the pending
  timer IRQ.
- **The `daifclr`+`isb` point at which a pending IRQ is taken.** `arm_daif_clear_i()`
  issues `msr daifclr, #2; isb`; the ISB is the context-synchronization point after
  which the unmasked, already-pending IRQ is taken. The returning-IRQ path performs
  no `daifclr` before `eret`: the restored `SPSR.I` (validated clear for worker
  frames) governs the post-`eret` mask instead.
